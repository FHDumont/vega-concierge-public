# Vega Concierge — Workshop App

E-commerce store with a **multi-agent assistant (LangGraph)** for Splunk workshops. Observability (Splunk Agent Observability) is **opt-in** via environment variables — the app runs standalone without credentials.

**Participant guide:** [`workshop/`](workshop/) folder (Hugo, served on the VM at `:1313`) or this repository's GitHub Pages.

## Structure

- `backend/` — FastAPI + LangGraph
- `frontend/` — Next.js + Tailwind (store, Behind the Scenes, Admin)
- `control/` — Vega Ops Console (VM maintenance from the browser)
- `workshop/` — Hugo workshop guide
- `scripts/` — dev, Docker, workshop boot
- `docker-compose.yml`, `compose.plain.yml`, `.env.example`

## How to run

**First run:** copy the production template and start the stack:

```bash
cp .env.example .env    # template for ./scripts/up.sh (GHCR pull)
./scripts/up.sh
```

Local dev (`./scripts/dev.sh` or `./scripts/up.sh --build`) runs the wizard and adjusts URLs for the host — see the `[dev]` comments in `.env.example`.

### Dev — hot reload, without Docker

```bash
./scripts/dev.sh               # wizard (if needed) + back (:8000) + front (:3000)
```

Standalone: doesn't need Docker or credentials.

The **Vega Ops Console** doesn't start together on the laptop — run it on-demand in another terminal (Ctrl+C stops it):

```bash
./scripts/control.sh           # Ops Console :9000 (+ ttyd :7681 if installed)
```

On the workshop EC2 the panel is a **systemd service**, always running — see *Run on the workshop* below.

### Lab — local Docker with build

```bash
./scripts/up.sh --build        # wizard (if needed) + docker compose up --build
```

Frontend `:3000` · backend `:8000`.

### Production / Workshop — ready images (pull, no local build)

Direct ports on the VM: store `:3000` · API `:8000` · Ops Console `:9000` · Hugo guide `:1313`.

```bash
./scripts/up.sh                # validate-prod-env + pull + up -d
./scripts/up.sh logs           # follow logs
./scripts/up.sh down           # stop (keeps the SQLite volume)
```

**Docker images:** generated by this repository's CI (GitHub Actions → public GHCR, multi-arch amd64+arm64). On the VM, **never** use `docker build` — pull only. Runbook: [`docs/reference/runbooks/deploy-pull-only.md`](docs/reference/runbooks/deploy-pull-only.md).

## Run on the workshop (EC2)

**New VM (no golden AMI):** clone + idempotent bootstrap (Docker, Ollama, Hugo, systemd, stack):

```bash
git clone https://github.com/FHDumont/vega-concierge-public.git /opt/vega-concierge
cd /opt/vega-concierge
sudo ./scripts/bootstrap-workshop-host.sh
```

Full runbook: [`docs/reference/runbooks/bootstrap-workshop-host.md`](docs/reference/runbooks/bootstrap-workshop-host.md).

**Golden AMI / reboot:** the clone inherits the deps; boot via `scripts/boot-workshop.sh` (systemd). See [`deploy-pull-only.md`](docs/reference/runbooks/deploy-pull-only.md).

| Surface | Port | Access |
| --- | --- | --- |
| Store (frontend) | 3000 | `http://<VM-IP>:3000` |
| API (backend) | 8000 | `http://<VM-IP>:8000` |
| Vega Ops Console | 9000 | `http://<VM-IP>:9000` |
| Workshop guide (Hugo) | 1313 | `http://<VM-IP>:1313` |

**Security Group:** open **3000, 8000, 9000, and 1313**. ttyd (`:7681`) stays on `localhost` only — terminal via the `/shell/` proxy on the panel.

Boot on the AMI: `scripts/boot-workshop.sh` via systemd. **New VM:** use `scripts/bootstrap-workshop-host.sh` (replaces manual install). Units: `sudo REPO_DIR=/opt/vega-concierge ./control/systemd/install.sh` (the bootstrap already calls this).

## Vega Ops Console

At the workshop, SSH is usually blocked. The panel (`http://<VM-IP>:9000`) manages the infra from the browser — stack state + SSH terminal in an iframe. Password: `CONTROL_PASSWORD` (only for the terminal). See `control/README.md`.

| Environment | How it starts |
| --- | --- |
| Dev (laptop) | `./scripts/control.sh` — on-demand |
| EC2 (workshop) | systemd (`control/systemd/install.sh`) |


## Traffic simulator — `/admin/simulator`

Generates synthetic traffic through the same path as a real checkout. Access via **Vega → Simulator**. **API** (fast) or **Browser** (Playwright/Chromium for RUM) modes. Browser variant: `BACKEND_IMAGE=vega-backend-browser` in `.env` + pull.

## Splunk RUM — `/admin/connection`

Owner pastes the Splunk RUM Browser Agent snippet in **Vega → Connection** and flips the toggle. Off by default.

## LLM — `/admin/config`

Cascading multi-provider with fallback to an offline stub — works **without keys**. Initial provider: Ollama (`OLLAMA_BASE_URL` in `.env`). Other providers via Admin (owner-only). First run: `./scripts/setup-wizard.sh`.

## Opt-in observability

- **Splunk Agent Observability:** `GALILEO_API_KEY` in `.env` (empty = base app, no traces).
